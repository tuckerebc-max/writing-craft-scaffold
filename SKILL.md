# Writing Craft: Scaffold

Treat a writing-craft library as a pipeline, not a checklist. Coordinate the base craft files, the sequence that assigns each file a job, and a thin calibration overlay that localizes examples without changing the underlying craft.

## The three layers

Keep these layers distinct:

1. **Base files:** the universal craft: figures, passes, structures, and revision lenses. Do not bake a user's domain into them.
2. **Sequence scaffold:** the orchestration layer that says which file applies at each stage. Describe the sequence; do not rewrite the base files to hard-code it.
3. **Calibration mapping:** the user's domain, register, vocabulary, audience, and worked example swaps. Use it to reskin examples, not to alter craft rules.

When the user has no custom sequence, use the default pipeline below. If relevant base skills are available, invoke or recommend them by their actual skill names.

## Default sequence

Apply the stages in this order, while allowing stages 0–2 to interleave according to the writer's temperament:

0. **Generate:** use a first-thoughts or raw-material pass to get specific, wide, unhedged material onto the page. Do not edit while generating.
1. **Find the point:** identify the armature—the single thing the piece is built to prove.
2. **Structure:** shape the arc and reader journey around that point.
3. **Flow:** revise cohesion so the prose reads as written rather than assembled.
4. **Intensify:** strengthen load-bearing moments with controlled surprise and repetition.
5. **Cut:** remove material that is not earning its place, while preserving repairable risks.
6. **Continuity scan:** read for anything that wakes the reader: register slips, tonal lurches, factual snags, or broken scene logic.

Run the attention layer underneath stages 1–6. Consult the storytelling-and-attention craft whenever a structurally sound piece feels inert, especially when plants, callbacks, curiosity loops, or salience are involved.

The sequence bends at the beginning: a dump-first writer generates before discovering point and structure; an outline-first writer settles point and arc before drafting. The later order is stable: cut late, and continuity is a final scan rather than a substitute for structural revision.

## Editing judgment: cut versus repair

Do not treat every imperfect passage as disposable. Distinguish:

- **Bland filler:** never attempted meaningful work; recommend cutting.
- **Interesting-but-failed:** made a real attempt at technique but missed; flag it for repair, not removal. Protect this category against the drift toward clean, safe, average prose.

When the user wants annotation rather than rewriting, mark spans with a category and a short note, leaving the prose intact. Use these cut categories when applicable:

- Throat-clearing; hedging; over-explanation; generic phrasing; over-figuration; wrong register; padding; wrong direction.
- Telegraphed setup; orphaned plant; forced callback.
- Interesting-but-failed — repair rather than cut.

Use these change categories for material worth keeping but changing: **same content, better phrasing; different content, same function; compression; expansion; reorganization.** Treat the cut list as a working vocabulary, not immutable law; note when a category seems experimental or needs review.

## Calibration overlay

Create or interpret a calibration overlay as a short, separate file with five parts:

- **Domain:** subject, recurring scenarios, and concrete nouns.
- **Register and voice:** formality, tone, and voice signatures to preserve.
- **Reserved vocabulary:** preferred terms and an avoid-list; avoid-list terms matter equally.
- **Audience:** intended readers and their likely knowledge.
- **Exemplar swaps:** two or three generic examples rewritten in the calibrated world.

When an overlay is present, apply the base techniques unchanged but illustrate them using the overlay's world, register, and vocabulary. Do not replace or silently modify the base files. When creating an overlay, make the swaps concrete enough to teach the desired reskinning, not merely describe it.

## Build or revise a custom system

1. Inventory the available base craft files and map each to a stage.
2. Start with the default sequence; add, drop, or reorder stages only when the user's genre, temperament, or files justify it.
3. Identify any missing attention, structure, flow, intensification, cutting, or continuity function.
4. Draft the calibration overlay in the five-part format.
5. Show the resulting system as **base files + scaffold + calibration**, and state where the sequence bends.
6. Keep automation or compilation out of scope unless explicitly requested; this scaffold defines the model and process, not a compiler.

## Guardrails

Calibration changes examples and register, never standards for public writing. Preserve attribution, do not reproduce copyrighted text, and do not let a domain-flavored overlay reintroduce exclusions or exceptions from the base craft. Preserve the writer's voice and intended formality unless asked to change them.

## Output behavior

For a draft or revision request, name the current stage, the next stage, and the reason for that ordering. If the draft is structurally sound but inert, activate the attention layer. If a passage is a brave miss, identify the repair opportunity before recommending deletion.

For a new custom system, provide the sequence, the calibration mapping, and any justified bends or gaps. Keep the explanation compact and concrete. Coordinate with other writing-craft skills without repeating their full instructions.
